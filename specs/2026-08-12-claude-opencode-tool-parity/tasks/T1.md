# Task 1: 统一 Claude 启动与 PTY 安全边界

## 描述

让 Claude create/resume 使用同一套经过校验且脱敏的长期 TUI 启动参数，补齐失败原子性、权限安全迁移、事件接线和 unsupported 回复 API。

## 依赖

- 前置 task：T2、T3
- 外部依赖：本机 Claude Code CLI 2.1.228 参数契约、现有 node-pty runtime

## 涉及文件

| 操作 | 文件路径 | 说明 |
| ---- | -------- | ---- |
| 修改 | `src/drivers/claude-driver.js` | 规范化 launch options、映射 transcript 事件、回复 API 降级、结构化诊断 |
| 修改 | `src/drivers/claude-pty-broker.js` | create/resume 公共参数、spawn 失败原子性、脱敏日志 |
| 修改 | `test/claude-driver.test.js` | 参数、权限、事件与 unsupported API 测试；保留历史列表测试 |
| 修改 | `test/claude-pty-broker.test.js` | create/resume 参数快照与故障注入 |

## 复杂度

high，原因：同时涉及长期进程生命周期、安全配置、兼容迁移和 driver 事件边界。

## 实现步骤

- [ ] 在测试中固定 create/resume 公共参数一致、长期 TUI 禁用 print/stream-json、未配置与显式空工具集合的差异。
- [ ] 在 driver 中集中规范化启动配置，校验 agents、MCP、settings、sources、plugins、权限模式及危险组合。
- [ ] 仅将脱敏后的参数类别交给日志，将完整值以 spawn 参数数组交给 broker。
- [ ] 修改 broker create/resume 接收统一公共参数；spawn 成功后才替换 runtime 状态，失败时保留可用旧 runtime 或清理新资源。
- [ ] 把 T2 的 text/reasoning/tool lifecycle/question/hook 事件映射到 AgentEvent，并保持 prompt 文本收集边界。
- [ ] 实现固定 unsupported permission/question reply 错误，确认调用不会写 PTY。
- [ ] 保持 sidecar 优先复用、精确 resume、输入 lease、attach/detach/stop 和历史列表现有语义。
