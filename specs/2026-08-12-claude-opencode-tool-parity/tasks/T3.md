# Task 3: 集中配置与 provider 能力面

## 描述

把新增 Claude 配置接入环境、管理配置和 bootstrap，并让 provider catalog 诚实展示 supported/degraded/unsupported 能力与限制。

## 依赖

- 前置 task：无
- 外部依赖：现有 `.env` 原子更新和 admin metadata 机制

## 涉及文件

| 操作 | 文件路径 | 说明 |
| ---- | -------- | ---- |
| 修改 | `.env.example` | 新增 Claude 配置示例并移除过期 default 默认值 |
| 修改 | `src/config/env.js` | 类型解析、空值语义和统一错误 |
| 修改 | `src/app/bootstrap.js` | 将规范化配置传入 ClaudeDriver |
| 修改 | `src/admin/config.js` | editable definitions、合法值和敏感标记 |
| 修改 | `src/admin/config-editor.js` | 新类型校验并保持整组原子写入 |
| 修改 | `src/providers/provider-catalog.js` | 配置键与详细 capability status |
| 修改 | 四个对应测试文件 | config/bootstrap/admin/catalog 契约测试 |

## 复杂度

high，原因：同一配置契约跨环境加载、持久化更新、driver 构造和管理能力展示，且必须兼容旧部署。

## 实现步骤

- [ ] 用配置表测试固定所有新增环境变量、列表/JSON/boolean 解析和缺省行为。
- [ ] 更新环境配置与 admin definitions，确保错误只显示配置键和允许范围。
- [ ] 保持 config editor 先全量规范化、后临时文件 rename 的原子更新流程。
- [ ] 更新 bootstrap 参数传递，保证每个字段只在集中配置层解析一次。
- [ ] 保留兼容所需顶层 capability 布尔字段，同时新增详细 `capabilityStatus`；Claude permission/question reply 不得标记 supported。
- [ ] provider catalog 解释 Claude 原生 tools/permission 与 OpenCode 规则非同构，OpenCode catalog 内容不变。
- [ ] 同步 `.env.example`，未配置新增字段时不改变启动默认值。

- executing 阶段为 7 条 behavior 补真实测试与 evidence。
- provider 与 admin 快照必须引用实际 schema，不能只验证字段存在。
