# Task 2: 完整解析 transcript 与工具生命周期

## 描述

以向后兼容方式扩展 AgentEvent，并让 Claude JSONL watcher 按顺序输出文本、思考、工具调用、工具结果及可靠的 question/hook 诊断。

## 依赖

- 前置 task：无
- 外部依赖：Claude Code 2.1.228 transcript 实际 JSONL 形状

## 涉及文件

| 操作 | 文件路径 | 说明 |
| ---- | -------- | ---- |
| 修改 | `src/drivers/agent-driver.js` | 为 tool lifecycle 增加可选关联字段，不改变旧生产者 |
| 修改 | `src/drivers/claude-transcript.js` | 多 block 解析、call ID 关联、未知事件限流、恢复 |
| 修改 | `test/claude-transcript.test.js` | 混合 fixture、orphan、部分行、未知事件与历史列表回归 |

## 复杂度

high，原因：解析器必须处理真实外部格式、增量 IO、乱序关联和兼容已有历史扫描逻辑。

## 实现步骤

- [ ] 先用 fixture 固定单 record 多 content block 的事件顺序和字段。
- [ ] 扩展 `tool_use` schema 的可选 `callID/phase/result/isError/orphan` 字段，确认 OpenCode 旧事件仍通过校验。
- [ ] 将 parser 从单事件改为有序事件列表，保留 text/reasoning/tool start/tool result 的原始关联信息。
- [ ] 跟踪已见 call ID；缺失 start 的 result 保留并标记 orphan，不跨 call 错绑。
- [ ] 仅映射真实稳定字段的 question/hook；敏感 payload 只输出允许摘要。
- [ ] 对未知 block 做固定上限的分类诊断，对坏记录或部分行保持 watcher 可恢复。
- [ ] 保护现有 cwd 编解码、head/tail metadata、全项目历史扫描和纯文本回复收集行为。
