# Task 2: Driver 续接与 fallback 决策

## 描述

修改 `ClaudeDriver` 和 `ClaudePtyBroker`，使 driver 在旧 sidecar runtime 可用时续接同一 runtime，不可用时才创建新的 `claude --resume` 受控 runtime。

## 依赖

- 前置 task：T1
- 外部依赖：无

## 涉及文件

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 修改 | `src/drivers/claude-driver.js` | 接入 sidecar lookup/reconnect，调整 `isSessionRefActive()`、`resumeSession()`、`prompt()`、状态字段和 fallback 日志。 |
| 修改 | `src/drivers/claude-pty-broker.js` | 支持 broker 与 sidecar runtime registry 的桥接，不在可续接路径创建第二个 PTY。 |
| 修改 | `test/claude-driver.test.js` | 覆盖旧 runtime 续接、fallback、调用顺序和兼容旧 agentRef。 |
| 修改 | `test/claude-pty-broker.test.js` | 覆盖 broker 与 sidecar registry 的交互和不可用判定。 |

## 复杂度

high，原因：该任务改变 Claude 会话恢复和 prompt 写入路径，影响现有生命周期语义。

## 实现步骤

- [ ] 为 `ClaudeDriver` 注入或创建 bridge/sidecar 客户端，保持测试可替换。
- [ ] 修改 `isSessionRefActive()`，按当前 broker runtime、可重连 sidecar runtime、不可用 stale runtime 三类返回准确状态。
- [ ] 修改 `resumeSession()`，优先 reconnect 旧 `runtimeId`；成功时返回包含 `runtimeStatus: 'reconnected'` 或等价状态的新 ref。
- [ ] 在旧 runtime 不可用时走现有 `ptyBroker.resumeRuntime({ claudeSessionId })` fallback，并打开新 attach TUI。
- [ ] 保证可续接旧 runtime 时不调用 `resumeRuntime()`、不调用 `openTerminal()`、不创建第二个 PTY/TUI。
- [ ] 记录 fallback/unavailable/reconnected 状态，日志和 ref 不包含 token、API key 或敏感环境变量。
- [ ] 编写 driver 和 broker 单元测试。
