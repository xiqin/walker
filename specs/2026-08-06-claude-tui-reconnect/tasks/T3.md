# Task 3: Dispatcher 消息路径原子续接

## 描述

调整 dispatcher 的 Claude agentRef 准备逻辑，确保重启后的 reconnect、持久化和 prompt 写入按原子顺序完成。

## 依赖

- 前置 task：T2
- 外部依赖：无

| 修改 | `test/message-dispatcher.test.js` | 覆盖续接成功、fallback、旧 terminal active 不误导、旧格式 agentRef 兼容和调用顺序。 |

## 复杂度

medium，原因：主要改动集中在消息调度边界，但必须保证状态持久化与 prompt 顺序。

## 实现步骤

- [ ] 扩展 `_prepareClaudeAgentRef()`，识别 driver 返回的 reconnected/fallback ref 并更新 `session.agentRef`。
- [ ] 保证 `_updateSessionRuntimeField(session.id, 'agentRef', ref)` 在 `driver.prompt()` 之前完成。
- [ ] 对旧 `terminal.status === 'active'` 但 driver 判定不可用的 ref，禁止直接写入旧 runtime。
- [ ] 保持缺少 bridge 字段的旧格式 Claude agentRef 可通过 `claudeSessionId` fallback。
- [ ] 为调用顺序、状态更新和 prompt 使用 ref 编写测试。
