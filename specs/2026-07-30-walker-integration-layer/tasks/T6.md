# Task 6: PlatformDriver 轻 adapter 与兼容收口

## 描述

定义 PlatformDriver 与 PlatformRegistry，将飞书入口轻 adapter 化为平台中立事件输入，同时保持现有飞书长连接、命令、卡片、附件、权限和问题处理兼容。

## 依赖

- 前置 task：T1、T3
- 外部依赖：飞书 SDK、现有 OpenCode session watcher、现有 dispatcher 状态机

## 涉及文件

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 创建 | `src/platforms/platform-driver.js` | 定义平台驱动接口与标准事件字段。 |
| 创建 | `src/platforms/platform-registry.js` | 管理平台驱动实例和状态。 |
| 创建 | `src/platforms/feishu-platform-driver.js` | 包装现有飞书平台，转换标准事件并代理发送能力。 |
| 修改 | `src/platform/feishu/platform.js` | 接入 adapter，不破坏原有长连接与卡片行为。 |

## 复杂度

high，原因：该任务触碰当前主消息链路和飞书兼容行为，必须用轻 adapter 方式渐进改造。

## 实现步骤

- [ ] 定义 PlatformDriver 接口，包含 start、stop、sendMessage、updateMessage、sendCard、uploadAttachment。
- [ ] 定义标准 platform event 校验，要求 platform、type、messageId、routeKey、userId、text、attachments。
- [ ] 实现 PlatformRegistry，用于后续多平台扩展但不连接真实新平台。
- [ ] 实现 FeishuPlatformDriver，将现有飞书消息对象转换为标准事件，并代理发送、卡片和附件能力。
- [ ] 在 `MessageDispatcher` 增加 `handlePlatformMessage(event)`，复用现有 dedup、route、session、turn 状态机。
- [ ] 对 invalid platform event 返回明确错误并确保不调用 driver。
- [ ] 记录 platform message received、delivery failed、adapter error 等事件或日志。
- [ ] 回归现有飞书平台、dispatcher、session service、integration 测试。
- [ ] 更新 README，说明新架构和本次不实现其他真实平台接入。
