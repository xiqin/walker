# Task 1: Provider Catalog 与 DriverRegistry 增强

## 描述

新增 Provider Catalog、检测服务和 DriverRegistry provider 元信息入口，让 Walker 能真实检测 opencode、claude、codex、shell 的安装、版本、配置、健康状态与 capabilities。

## 依赖

- 前置 task：无
- 外部依赖：本机命令解析、OpenCode HTTP server 可选健康检查

## 涉及文件

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 创建 | `src/providers/provider-catalog.js` | 定义 opencode、claude、codex、shell 的 provider 元信息与 capabilities。 |
| 创建 | `src/providers/provider-detectors.js` | 封装命令查找、版本命令、超时和失败结构化。 |
| 创建 | `src/providers/provider-health.js` | 聚合 provider doctor/list 状态，隔离单 provider 异常。 |
| 修改 | `src/drivers/driver-registry.js` | 保持 `list()` 兼容，新增 provider metadata/status 查询入口。 |
| 修改 | `src/admin/agent-runtime-admin.js` | Admin agent 状态复用 provider 检测结构。 |
| 创建 | `test/provider-catalog.test.js` | 覆盖 provider 成功、未知 id、外部失败和恢复路径。 |
| 创建 | `test/driver-registry.test.js` | 覆盖 register/unregister/clear 与 provider metadata 一致性。 |

## 复杂度

high，原因：该任务是后续 CLI、API、init 和 Admin 状态的共同底座，且要处理外部命令失败与兼容现有 registry 行为。

## 实现步骤

- [ ] 定义 provider catalog 数据结构，包含 `id`、`label`、`driver`、`executableCandidates`、`versionCommand`、`healthCheck`、`capabilities`、`configKeys`。
- [ ] 实现 shell 内建 provider 检测，确保无外部可执行文件也能返回 installed 与 healthy 状态。
- [ ] 实现命令解析、版本命令、超时和健康检查失败的结构化结果，填充 `problems` 与 `suggestions`。
- [ ] 增强 `DriverRegistry`，新增 provider catalog 注入、provider 查询和 doctor 方法，保持 `list()` 只返回已注册 driver 名称。
- [ ] 调整 `agent-runtime-admin` 复用 provider 状态，不破坏 `/api/admin/agents` 的现有响应。
- [ ] 补充 provider 与 registry 测试，覆盖单 provider 异常不影响整体返回。
