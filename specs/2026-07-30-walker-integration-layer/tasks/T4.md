# Task 4: `walker init` 初始化体验

## 描述

实现 `walker init`，在首次使用或资源缺失时创建 Walker 数据目录、状态文件、配置模板、安全 token 提示和 OpenCode TUI plugin 检查，且保持幂等与安全写入。

## 依赖

- 前置 task：T1、T2
- 外部依赖：用户数据目录、文件系统权限、OpenCode TUI plugin 安装路径

## 涉及文件

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 创建 | `src/cli/init-command.js` | 实现 init 主流程、目录创建、配置模板和 plugin 检查。 |
| 创建 | `src/cli/safe-write.js` | 提供 JSON 安全写入、已存在文件保护和失败恢复。 |
| 创建 | `test/init-cli.test.js` | 覆盖首次创建、幂等、安全、atomicity 和恢复场景。 |

## 复杂度

medium，原因：功能集中在文件系统写入，但必须避免覆盖用户配置或留下损坏 JSON。

## 实现步骤

- [ ] 实现数据目录解析，支持临时测试目录注入并默认使用 `~/.walker`。
- [ ] 创建 `state.json`、`dedup.json`、`attachments/`、`logs/` 和 `config.json` 模板，已有文件不覆盖。
- [ ] 生成或提示 `WALKER_ADMIN_TOKEN`，输出只显示脱敏结果或写入位置。
- [ ] 检查 OpenCode TUI plugin 状态，执行明确允许的安装或刷新路径。
- [ ] 使用安全写入，写入失败时不留下不可解析 JSON。
- [ ] 对缺失目录执行恢复，对损坏配置报错并保留原文件。
- [ ] 确认 init 不修改 shell profile、系统服务或第三方平台密钥。
