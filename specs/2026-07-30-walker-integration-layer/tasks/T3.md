# Task 3: 稳定 `/api/v1` HTTP API

## 描述

新增 `/api/v1` 路由层，稳定暴露 providers、sessions、routes、prompt、events、metrics 能力，并复用现有 Admin auth、response、session、route 和 event 服务。

## 依赖

- 前置 task：T1
- 外部依赖：本机 HTTP 请求、`WALKER_ADMIN_TOKEN`

## 涉及文件

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 创建 | `src/api/v1/index.js` | 注册 v1 路由集合。 |
| 创建 | `src/api/v1/providers-routes.js` | 暴露 provider list 与 provider doctor。 |
| 创建 | `src/api/v1/sessions-routes.js` | 暴露 session list/create/detail/stop/delete/cancel。 |
| 创建 | `src/api/v1/routes-routes.js` | 暴露 route list/detail/focus/unfocus。 |
| 创建 | `src/api/v1/prompt-routes.js` | 暴露稳定 prompt API 和输入校验。 |
| 创建 | `src/api/v1/events-routes.js` | 暴露 events 与 metrics HTTP 查询。 |
| 修改 | `src/admin/router.js` | 将 `/api/v1/` 纳入受保护 API 路径。 |
| 修改 | `src/app/bootstrap.js` | 注册 v1 路由到 Admin server。 |
| 创建 | `test/api-v1.test.js` | 覆盖 v1 成功、错误、事件记录和 admin 兼容。 |
| 创建 | `test/api-v1-auth.test.js` | 覆盖 token 缺失和错误 token。 |

## 复杂度

high，原因：这是未来 Admin、平台入口和第三方集成的稳定边界，必须兼容现有 Admin 路由并避免暴露内部 state 结构。

## 实现步骤

- [ ] 建立 `src/api/v1/` 路由注册结构，复用 `success`、`error`、`send` 和 `parseBody`。
- [ ] 实现 providers API，调用 T1 provider health service。
- [ ] 实现 sessions 与 routes API，复用 `session-admin` 和 `route-admin` 的稳定 DTO。
- [ ] 实现 prompt API，校验 `text` 以及 `routeKey/sessionId`，无效输入不调用 driver。
- [ ] 实现 events 与 metrics HTTP API，复用 event-store 查询。
- [ ] 把 `/api/v1/` 纳入现有 auth guard，并在 bootstrap 中注册路由。
- [ ] 确认 `/api/admin/*` 路由和既有测试不回退。
