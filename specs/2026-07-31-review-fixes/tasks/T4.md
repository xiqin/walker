# Task 4: API v1 错误与 Prompt Events 脱敏

## 描述

阻止 API v1 客户端响应泄漏内部异常消息或 driver 原始事件秘密，同时保留服务端可观测性和 prompt 成功响应。

## 依赖

- 前置 task：无
- 外部依赖：无

## 涉及文件

| 操作 | 文件路径 | 说明 |
| ---- | -------- | ---- |
| 修改 | `src/api/v1/common.js` | API wrapper 内部错误响应去除原始异常消息 |
| 修改 | `src/api/v1/prompt-routes.js` | prompt events 返回前脱敏或转换为安全 DTO |
| 修改 | `test/api-v1.test.js` | 更新错误响应和 prompt events 脱敏测试 |

## 复杂度

medium，原因：安全输出策略影响 API 断言，但文件边界集中。

## 实现范围

- 调整 `src/api/v1/common.js` 的统一异常响应，不返回原始 `err.message`。
- 在 `src/api/v1/prompt-routes.js` 对 `result.events` 做递归脱敏或安全 DTO 转换。
- 复用现有脱敏实现时避免引入循环依赖；必要时抽出局部安全 sanitizer。
- 更新 `test/api-v1.test.js` 中内部错误和 prompt events 断言。

## 实现步骤

- [ ] 修改或新增 API handler 抛 `Error('doctor exploded')` 的测试，断言响应不包含 `doctor exploded`。
- [ ] 添加 eventStore 可观测断言，确认仍记录 `api.v1.error`。
- [ ] 添加 prompt API 脱敏测试，覆盖敏感 key、Bearer 文本和 env secret 文本。
- [ ] 保持正常 prompt 成功响应结构 `{ sessionId, events }` 或明确安全 DTO 结构。
- [ ] 运行 `node --test test/api-v1.test.js`。

## 验收映射

- `REQ-004-B01`：INTERNAL_ERROR 不返回内部异常文本。
- `REQ-004-B02`：prompt events 递归脱敏敏感 key 和 secret 文本。
- `REQ-004-B03`：内部错误仍记录到 eventStore/logger。
- `REQ-004-B04`：正常 prompt 请求仍成功并返回安全事件数据。

## 注意事项

- 客户端错误格式保持统一 `{ ok:false, error }`。
- 不删除 `events` 字段，除非测试和兼容性确认可接受；优先脱敏保留。

## 测试说明

- 测试文件：`test/api-v1.test.js`
- 覆盖场景：内部错误不泄漏、eventStore 可观测、prompt events 脱敏、prompt 正常成功
- 验证命令：`node --test test/api-v1.test.js`
