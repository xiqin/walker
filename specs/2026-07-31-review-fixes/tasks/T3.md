# Task 3: Provider Detector 最小环境

## 描述

确保 provider 诊断执行 `where`/`which` 和 provider `--version` 等外部命令时，不继承 Walker、飞书、API key 等敏感环境变量，同时保留跨平台命令解析所需变量。

## 依赖

- 前置 task：无
- 外部依赖：本机 PATH 中的 provider 命令通过测试注入替代

## 涉及文件

| 操作 | 文件路径 | 说明 |
| ---- | -------- | ---- |
| 修改 | `src/providers/provider-detectors.js` | 增加最小 env 构造并用于外部命令执行 |
| 修改 | `test/provider-catalog.test.js` | 增加 env 构造或 provider detector 覆盖 |
| 修改 | `test/providers-cli.test.js` | 验证 provider CLI 输出脱敏和状态稳定 |
| 修改 | `test/doctor-cli.test.js` | 验证 doctor 路径不泄漏敏感输出 |

## 复杂度

medium，原因：命令执行安全敏感，但实现集中在 detector 层。

## 实现范围

- 在 `src/providers/provider-detectors.js` 增加最小环境构造函数。
- `runCommand()` 和 `defaultResolveCommand()` 使用最小 env，测试可注入覆盖。
- 保持 provider version 失败时返回结构化 problem/suggestion。
- 通过 provider/doctor CLI 测试确认输出脱敏。

## 实现步骤

- [ ] 添加单元测试覆盖最小 env 保留平台必要变量并剔除敏感变量。
- [ ] 添加 `runCommand()` 测试，捕获传给 `execFile` 的 `options.env`。
- [ ] 添加 `defaultResolveCommand()` 测试，确认 lookup 命令也使用受限 env。
- [ ] 保持 provider version 失败测试通过，返回 `VERSION_FAILED` problem 和 suggestion。
- [ ] 运行 `node --test test/provider-catalog.test.js test/providers-cli.test.js test/doctor-cli.test.js`。

## 验收映射

- `REQ-003-B01`：子进程 env 不包含 token/secret/password/api key。
- `REQ-003-B02`：最小环境保留平台必要变量。
- `REQ-003-B03`：version command 失败结构化返回。
- `REQ-003-B04`：CLI 输出错误经过脱敏层。

## 注意事项

- 不把 provider discovery 改成纯 Node PATH 解析，除非最小 env 无法满足测试。
- 测试应避免真实执行本机 provider 命令，优先注入 fake runner。
