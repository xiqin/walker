# Task 2: WebSocket 安全、限流与关闭释放

## 描述

加固 `/api/v1/events/stream` 的浏览器安全边界和资源控制，确保 server stop 主动释放 WebSocket 客户端和 eventBus 订阅。

## 依赖

- 前置 task：T1
- 外部依赖：`ws`

## 涉及文件

| 操作 | 文件路径 | 说明 |
| ---- | -------- | ---- |
| 修改 | `src/admin/ws-events.js` | 增加 Origin 校验、payload/filter 限制、无效消息关闭和主动断连 |
| 修改 | `src/admin/server.js` | 保持 upgrade/stop 释放顺序与 WS handler 集成 |
| 修改 | `test/events-websocket.test.js` | 增加 Origin、资源限制和 stop 释放测试 |

## 复杂度

high，原因：涉及网络连接生命周期、安全策略和资源释放。

## 实现范围

- 在 `src/admin/ws-events.js` 增加 Origin 校验。
- 设置 WebSocket payload 限制、filter 字段长度限制和连续无效消息关闭策略。
- 在关闭路径中主动 `close()` 或 `terminate()` 已连接客户端。
- 在 `src/admin/server.js` 中保持 upgrade 集成兼容，并确保 stop 顺序释放 WS 资源。
- 补充 `test/events-websocket.test.js` 的安全与资源释放测试。

## 实现步骤

- [ ] 添加恶意 Origin 测试：带合法 cookie 但 `Origin: https://evil.example` 的连接被拒绝。
- [ ] 添加无 Origin 的非浏览器客户端仍可连接的兼容测试。
- [ ] 添加超大 payload 或超长 filter 测试，期望拒绝错误或关闭连接。
- [ ] 添加连续非法 JSON/unsupported type 达阈值后关闭连接测试。
- [ ] 添加 `adminServer.stop()` 主动关闭已连接客户端并释放订阅的测试。
- [ ] 实现 Origin allowlist、`maxPayload`、filter normalization 限制、bad message counter 和 close 逻辑。
- [ ] 运行 `node --test test/events-websocket.test.js`。

## 验收映射

- `REQ-002-B01`：未授权 upgrade 返回 401。
- `REQ-002-B02`：恶意 Origin 被拒绝。
- `REQ-002-B03`：payload/filter 受限。
- `REQ-002-B04`：server stop 释放客户端连接和订阅。
- `REQ-002-B05`：拒绝、错误、关闭路径可观测且脱敏。
- `REQ-002-B06`：连续无效消息不会无限保持连接。

## 注意事项

- Cookie 鉴权的浏览器连接必须校验 Origin。
- 为兼容脚本客户端，缺失 `Origin` 的请求允许继续走 token/cookie 鉴权。
- 事件记录不得包含 cookie、Authorization 或 token 明文。
