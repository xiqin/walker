# Task 5: 飞书 Platform Event 边界与可观测失败

## 描述

让飞书标准 platform event 兼容合法边界输入，避免 sender ID 变体或空文本在 adapter 层被静默丢弃，并让不可恢复转换失败进入可观测路径。

## 依赖

- 前置 task：无
- 外部依赖：飞书事件结构通过测试 fixture 构造

## 涉及文件

| 操作 | 文件路径 | 说明 |
| ---- | -------- | ---- |
| 修改 | `src/platforms/platform-driver.js` | 放宽 text 空字符串校验并保留结构校验 |
| 修改 | `src/platforms/feishu-platform-driver.js` | 修复标准/已解析事件字段兼容和 adapter error 口径 |
| 修改 | `src/platform/feishu/events.js` | 增加 sender ID fallback 和标准事件字段兼容 |
| 修改 | `src/platform/feishu/platform.js` | adapter 转换失败进入可观测路径 |
| 修改 | `test/platform-driver.test.js` | 校验空 text 与 invalid-input 边界 |
| 修改 | `test/feishu-platform-driver.test.js` | 校验 sender fallback 和标准字段兼容 |
| 修改 | `test/message-dispatcher-platform-event.test.js` | 保持 dispatcher platform event 行为 |
| 修改 | `test/bootstrap.test.js` | 保持飞书分发路径行为 |

## 复杂度

high，原因：涉及平台 adapter、标准事件校验和分发路径交互。

## 实现范围

- 调整 `src/platform/feishu/events.js` 的 sender ID fallback 和标准事件字段兼容。
- 调整 `src/platforms/platform-driver.js`，允许 `text: ''` 但仍校验必需结构字段。
- 调整 `src/platforms/feishu-platform-driver.js`，明确或修复已解析/标准化事件输入兼容。
- 调整 `src/platform/feishu/platform.js` 的 adapter 失败观测路径。
- 更新 platform、feishu driver、dispatcher platform event 和 bootstrap 测试。

## 实现步骤

- [ ] 添加 `open_id` 缺失但 `user_id` 或 `union_id` 存在的飞书事件测试，断言 `platformEvent.userId` 非空。
- [ ] 添加 `validatePlatformEvent({ text: '' })` 通过测试。
- [ ] 添加缺失 `messageId` 或 `routeKey` 的不可恢复事件仍被拒绝的测试。
- [ ] 添加 `FeishuPlatform._handleMessageEvent()` adapter 转换失败时产生 `platform.adapter_error` 可观测事件的测试。
- [ ] 添加空文本或 sender fallback 不直接静默 return 的分发测试。
- [ ] 实现 fallback、空文本校验放宽、标准字段兼容和 adapter error 观测。
- [ ] 运行 `node --test test/platform-driver.test.js test/feishu-platform-driver.test.js test/message-dispatcher-platform-event.test.js test/bootstrap.test.js`。

## 验收映射

- `REQ-005-B01`：open_id/user_id/union_id fallback。
- `REQ-005-B02`：空 text 通过平台校验。
- `REQ-005-B03`：不可恢复结构仍被明确拒绝。
- `REQ-005-B04`：adapter 转换失败可观测。
- `REQ-005-B05`：可恢复字段缺失不再静默丢弃。

## 注意事项

- 不重构完整多平台回复通道。
- 空文本是否回复由业务层决定，本任务只避免 adapter 层过早失败。
- 需要避免 adapter 与 dispatcher 未来重复记录同一语义事件；如调整事件名，测试需固定口径。
