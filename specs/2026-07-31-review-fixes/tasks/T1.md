# Task 1: Admin Auth Session 隔离

## 描述

修复 admin 登录 session 的全局共享问题，使登录 sid 只在当前 auth 实例或当前 token realm 内有效，并保持同 server 登录后的 cookie 访问能力。

## 依赖

- 前置 task：无
- 外部依赖：无

## 涉及文件

| 操作 | 文件路径 | 说明 |
| ---- | -------- | ---- |
| 修改 | `src/admin/auth.js` | 调整 session store 作用域或 realm 绑定校验 |
| 修改 | `test/api-v1-auth.test.js` | 增加跨 server sid 隔离和失败响应断言 |

## 复杂度

medium，原因：鉴权状态语义敏感，但涉及文件少且接口保持兼容。

## 实现范围

- 调整 `src/admin/auth.js` 中 session store 的作用域或 session entry 绑定信息。
- 保持 `POST /api/admin/auth/login` 与 `GET /api/admin/auth/status` 响应格式兼容。
- 保持未配置 token 时免鉴权行为不变。
- 不移除 legacy cookie 支持，除非实现过程中发现无法安全兼容。

## 实现步骤

- [ ] 在 `test/api-v1-auth.test.js` 添加跨 server sid 复用返回 401 的失败测试。
- [ ] 添加同 server 登录 sid 访问受保护 API 成功测试。
- [ ] 添加 401 响应不包含 token/sid 明文的断言。
- [ ] 实现实例级 session store，或在 session entry 中保存当前 token hash/realm 并在 `isAuthenticated()` 校验。
- [ ] 运行 `node --test test/api-v1-auth.test.js`。

## 验收映射

- `REQ-001-B01`：同一 server 使用登录 sid 认证通过。
- `REQ-001-B02`：不同 token server 不能复用 sid。
- `REQ-001-B03`：session 状态不再是无 realm 全局凭据。
- `REQ-001-B04`：认证失败响应不泄漏 token/sid。

## 注意事项

- 如果保留模块级工具函数 `isAuthenticated(req, config)`，需要确保它无法只凭全局 sid 放行不同 config。
- Bearer admin token 与 cookie sid 的处理路径应清晰，避免把 sid 当作跨实例 Bearer 凭据。

## 测试说明

- 测试文件：`test/api-v1-auth.test.js`
- 覆盖场景：同实例 cookie 登录、跨 token 实例拒绝、401 不泄漏凭据
- 验证命令：`node --test test/api-v1-auth.test.js`
