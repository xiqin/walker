# Task 6: safeWriteJson No-Clobber 竞态修复

## 描述

修复 `safeWriteJson(file, value, { overwrite:false })` 的检查后并发创建竞态，确保不覆盖调用期间由其他进程创建的目标文件，并保持失败清理语义。

## 依赖

- 前置 task：无
- 外部依赖：无

## 涉及文件

| 操作 | 文件路径 | 说明 |
| ---- | -------- | ---- |
| 修改 | `src/cli/safe-write.js` | 实现 no-clobber 写入或提交语义 |
| 修改 | `test/init-cli.test.js` | 增加竞态和失败清理测试 |

## 复杂度

medium，原因：文件写入语义需要兼容平台并覆盖失败清理。

## 实现范围

- 调整 `src/cli/safe-write.js` 的 no-clobber 提交流程。
- 保持已有有效 JSON 文件不覆盖且验证可读。
- 保持 `overwrite:true` 显式覆盖能力。
- 在 `test/init-cli.test.js` 或安全写相关测试中补充竞态 mock。

## 实现步骤

- [ ] 保留已有目标文件不覆盖测试。
- [ ] 添加 mock fs 竞态测试：初始 `accessSync` 显示不存在，但提交阶段目标已存在，期望不覆盖并返回或抛出明确结果。
- [ ] 添加写入或提交失败时临时文件清理测试。
- [ ] 实现原子 no-clobber 语义，可使用 `openSync(filePath, 'wx')` 或等效策略。
- [ ] 确认成功写入前后 JSON 可 parse，失败不留下半写目标。
- [ ] 运行 `node --test test/init-cli.test.js`。

## 验收映射

- `REQ-006-B01`：overwrite=false 已有文件不覆盖且验证 JSON 可读。
- `REQ-006-B02`：检查后目标并发创建不覆盖。
- `REQ-006-B03`：成功 JSON parse 校验，失败不留下半写目标。
- `REQ-006-B04`：写入或提交失败清理临时文件并返回明确错误。

## 注意事项

- Node 的 `renameSync` 在部分平台会替换目标文件，不能作为 no-clobber 提交手段。
- 如果使用 `openSync('wx')` 直接创建目标，需先序列化并 parse 校验内存中的 JSON，再写入目标文件。

## 测试说明

- 测试文件：`test/init-cli.test.js`
- 覆盖场景：已有文件不覆盖、检查后并发创建不覆盖、失败清理、成功 JSON 可 parse
- 验证命令：`node --test test/init-cli.test.js`
