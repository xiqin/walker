# 真实会话标题修复方案（已确认）

## 问题与证据

- 用户反馈：飞书页脚显示 `session wks_M7A3D1RA`，期望与所附 OpenCode 标签页标题一致。截图作为会话附件保留，不从截图推测完整标题文本。
- 本地 `SessionService.createSession` 在缺少标题时生成 `session <Walker短ID>`。
- TUI 桥接 `register` 和 hook 自动纳入创建会话时未传入标题，现有页脚直接读取本地 `session.title`。
- TUI 插件未订阅标题变更；因此只修改新会话创建不能修复已纳入会话。
- 已运行发送边界探针复现。持久化探针位于 `evidence/title-source-probe.cjs`，预期来自用户报告，网络在真实 `FeishuApi.sendText` 请求边界截获。

## 方案比较

### A．按关联会话读取真实标题并缓存（推荐）

- 在 OpenCode 驱动中增加只读标题能力，以精确 `agentRef.opencodeSessionId` 查询，而不是按当前焦点、cwd 或最近会话猜测。
- 普通连接通过已有 HTTP 客户端读取 `GET /api/session/{sessionID}`；TUI 连接优先复用现有本地数据库只读访问方式读取同一会话标题。具体表结构在计划前确认。
- 在页脚运行时组装时调用；成功结果与失败结果均最多缓存 30 秒，同一连接、同一会话并发读取共用一次进行中的请求。连接标识变化不能复用旧缓存。
- 单次读取受 2 秒预算约束；标题不可用不得阻断正文、卡片或提问发送。失败优先使用曾取得的真实标题或非默认本地标题，否则省略会话行，绝不把 Walker 自动默认名当真实标题。
- 不写回 Walker 会话名称，不改会话路由、焦点、模型与上下文计算，不修改插件协议；已纳入会话无需重新纳入。
- 成本：需要一次小范围只读查询；标题变更最多有 30 秒缓存延迟。现有“发送不查询标题”的测试约束须改为“查询有上限且不写状态”。

### B．插件上报创建及重命名事件

- 插件读取并上报标题，桥接更新本地元数据，页脚继续读本地。
- 优点：新会话标题更新及时，发送链路不查询。
- 缺点：涉及插件与桥接协议，旧插件和已纳入会话需要补读或升级，范围明显更大。

### C．每次发送即时查询

- 优点：实现较少，标题不受缓存延迟影响。
- 缺点：每次进度卡更新均增加查询与失败等待，放大外部依赖；不推荐。

## 验收边界

1. 本地为 `session wks_…` 且关联 OpenCode 有真实标题时，文本、Markdown、进度卡、问题卡均使用真实标题。
2. 已纳入旧会话、后续重命名、焦点切换及同 cwd 多会话，不串标题；缓存过期后下一次发送重新读取。
3. HTTP 非成功、超时、数据库不可用、空标题与非字符串标题都不得阻断发送；不回退到自动名称。
4. 查询有缓存、并发合并与时间预算，无标题写入、无新增远程修改；多行折叠及卡片转义沿用既有实现。
5. 回归保留旧页脚替换、正文去重、进度卡参数位置、模型与上下文行为。

## 非目标

不追溯修改已经发出的历史飞书消息；不根据 ID 或提示词生成伪标题；不提交、合并、推送、部署或重启服务。
