# 飞书页脚显示关联 OpenCode 真实会话标题

## 已确认意图

用户报告页脚显示 `session wks_M7A3D1RA` 而非 OpenCode 标签页标题，随后说明一个飞书会话进程绑定多个 OpenCode 会话。已展示按关联会话读取、按连接与会话隔离缓存的推荐方案；用户明确回复“实施吧”。该回复确认需求与方案，不代替后续实现计划的人工审批。

原始反馈与截图引用见 `source-input.md`、`sources/SRC-001/v1.txt`；截图保留在会话附件，不推断截图中被截断的完整标题。示例标题只用于合成测试。

## 方案与边界

选择 `design-proposal.md` 的方案 A，不选择插件协议扩展或每次发送无缓存查询。

- 通过驱动提供精确关联 OpenCode 会话的只读标题能力。普通连接复用现有 HTTP 客户端；TUI 复用现有数据库读取能力，表结构和权限须在计划阶段确认。
- 缓存及进行中请求均按连接标识与 `opencodeSessionId` 隔离，不能按飞书聊天、进程、cwd 或当前焦点共用标题。连接标识包含相应服务端地址或 TUI runtime 标识；切换底层会话或连接后不得复用旧缓存。
- 有效及失败结果缓存期限为 30 秒。期限内同键并发只执行一次读取；过期后的下一次发送刷新。单次标题读取总等待预算为 2 秒，HTTP 与子进程须具备实际超时或终止措施，不只使用遗留后台任务的竞争等待。
- 不写回 Walker 会话名称，不修改 OpenCode 标题或任何远程状态；仅构造可选 `runtime.sessionTitle`。
- 已纳入旧会话无需重新纳入或升级插件即可在标题源可用时获得真实标题。

## 需求

### REQ-001：真实标题与单会话归属

飞书文本、Markdown、进度卡和问题卡必须显示消息所属 OpenCode 会话的真实标题。不能把 Walker 自动生成的 `session <短ID>`、默认 `opencode <短ID>` 或仅有 ID 的占位名称作为真实标题。查询仅使用已关联的 `agentRef.opencodeSessionId`，不枚举最近会话猜测。

验收：本地名称仍为默认值、OpenCode 标题存在时，真实发送边界的页脚包含远端标题，不包含默认名，模型与上下文保持不变。

### REQ-002：一对多绑定、并发与标题更新

同一飞书聊天同时绑定 A、B 等会话时，各自输出携带各自标题；当前焦点切到 B 不得改变 A 迟到消息的标题。缓存和进行中读取按连接与会话隔离，过期后读取该会话最新标题；同 ID 不同服务端或 runtime 也不能串用。

验收：A、B 并发及焦点切换时标题归属正确；同键并发读取合并，异键独立；30 秒缓存过期后下一次发送采用更新标题。

### REQ-003：失败降级、旧会话与既有行为兼容

读取非成功响应、超时、数据库不可用、空或非字符串标题时，不得阻断正文、卡片或提问。优先保留同一关联身份曾取得的有效真实标题，其次使用有效且非默认的本地标题，否则省略会话行。无关联会话不得查询或从当前焦点猜测标题；显式会话无法解析时也不得回退到其他焦点会话。

验收：标题读取失败仍发送消息，模型、上下文不变；没有有效标题就省略会话行；旧会话首次读取能够获取真实标题；失败缓存防止重复查询，缓存过期后恢复读取；全过程无会话状态写入。

## 不变量与安全

- 保留既有会话路由、绑定、焦点选择、模型和上下文计算语义。
- 保留多行标题折叠、Markdown 与飞书标签转义、旧页脚替换及完成正文去重。
- 保留进度卡可选初始事件参数补位，不修改调用方参数数组。
- SQL 使用精确会话 ID 并安全转义，数据库只读访问；HTTP 只查询已关联会话的既有连接，不根据标题或外部输入新增目标地址。
- 缓存有界并在调度器销毁时清理；读取失败日志不输出认证信息或完整消息正文。

## 非目标

不修改历史飞书消息，不从提示词或 ID 生成伪标题，不变更插件协议，不变更会话管理命令；不自动提交、合并、推送、部署或重启服务。
