# Task 1: `/new --cwd` 解析与会话创建

## 描述

在 `MessageDispatcher._cmdNew` 中支持 `/new [agent] [title] --cwd <projectPath>`，并保证无效 `--cwd` 不创建任何会话。

## 依赖

- 前置 task：无
- 外部依赖：无

## 涉及文件

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 修改 | `src/dispatch/message-dispatcher.js` | 解析 `/new` 专属 `--cwd` 选项，确定本次新会话 cwd。 |
| 修改 | `test/message-dispatcher.test.js` | 增加指定 cwd、默认 cwd 兼容、缺值错误与不创建会话断言。 |

## 复杂度

medium，原因：涉及命令参数语义、异步 driver 调用、Walker session 状态和错误路径副作用控制。

## 实现步骤

- [ ] 步骤 1：在 `test/message-dispatcher.test.js` 增加 `/new --cwd H:\project` 测试，断言 `driver.createSession` 与 `sessionService.createSession` 均收到 `H:\project`。
- [ ] 步骤 2：增加 `/new opencode my-session --cwd H:\project` 测试，断言 agent/title 保持原语义且 cwd 生效。
- [ ] 步骤 3：增加未提供 `--cwd` 的回归断言，确认继续使用 dispatcher `defaultCwd`。
- [ ] 步骤 4：增加 `/new opencode my-session H:\project` 回归测试，断言第三个裸参数不会覆盖默认 cwd。
- [ ] 步骤 5：增加 `/new --cwd` 错误路径测试，断言响应包含 `--cwd` 与 path/cwd 说明，且 driver/sessionService 未调用、当前绑定未改变。
- [ ] 步骤 6：在 `_cmdNew` 中从 `cmd.args` 提取最后一个有效 `--cwd` 值并移除所有 `--cwd` 与对应值，再解析 agent/title。
- [ ] 步骤 7：当任一 `--cwd` 缺少后续值时通过 `sendErrorCard` 返回错误并提前结束。
- [ ] 步骤 8：将解析出的 cwd 用于 `driver.createSession({ title, cwd, model })` 和 `sessionService.createSession({ ..., cwd })`。
