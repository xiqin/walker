# T4 Admin 后端清空日志接口

## 目标

在 Admin 后端提供清空日志能力，清理当前项目日志目录中的允许列表日志文件及其归档，同时保持现有 `/api/admin/logs` 读取兼容性。

## 实现要求

- 在 `src/admin/file-admin.js` 中新增清空函数，例如 `clearLogs(options)`。
- 清空范围只包括：`walker.out.log`、`walker.err.log`、`walker.log`、`walker-out.log`、`walker-err.log` 及其数字归档。
- 当前日志文件优先截断为 0 字节，归档文件可以删除；文件不存在视为成功。
- 不接受来自请求的任意路径，不删除 `logs/` 外文件，不删除 `logs/keep.txt` 等非日志文件。
- 部分文件失败时返回明确失败列表，路由不得静默返回全成功。
- 在 `src/admin/maintenance-routes.js` 中新增清空日志路由，沿用现有 Admin 路由与认证边界。
- 保持 `readLogs` 只读取当前日志文件，不承诺读取归档内容。

## TDD 步骤

1. 在 `test/admin-files-diagnostics.test.js` 中覆盖清空当前日志和归档日志。
2. 覆盖空日志目录连续清空两次仍成功。
3. 覆盖 logs 外哨兵文件和 `logs/keep.txt` 不被删除。
4. 覆盖部分文件系统失败时返回失败列表。
5. 覆盖新增路由成功响应和非授权请求不执行清空。
6. 修改 `src/admin/file-admin.js` 和 `src/admin/maintenance-routes.js` 使测试通过。
