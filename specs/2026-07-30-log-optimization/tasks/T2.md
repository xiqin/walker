# T2 调整结构化 logger 文件写入策略

## 目标

让 `createLogger()` 默认只输出结构化日志到 `stderr`，不再额外写 `logs/walker.log`。当用户显式设置 `WALKER_LOG_FILE=true` 时，恢复写入 `logs/walker.log`，并在打开文件流前使用 T1 的轮转工具。

## 实现要求

- 修改 `src/core/logger.js` 的文件写入开关逻辑：未设置 `WALKER_LOG_FILE` 时不创建 `walker.log`。
- `WALKER_LOG_FILE=true` 时创建 `logs/walker.log` 并写入结构化 JSON。
- `WALKER_LOG_FILE=false` 时不创建也不追加 `walker.log`。
- 打开 `walker.log` 写入流之前调用轮转工具。
- 保持 `stderr` 输出、`WALKER_LOG_LEVEL` 过滤和敏感字段脱敏行为不变。
- 如有必要，为测试暴露仅限测试使用的重置能力，但不得影响生产 API 使用方式。

## TDD 步骤

1. 新增或补充 `test/logger.test.js`，覆盖默认环境下不会创建 `walker.log`。
2. 覆盖 `WALKER_LOG_FILE=true` 时写入 `walker.log`。
3. 覆盖 `WALKER_LOG_FILE=false` 时不写文件。
4. 覆盖敏感字段脱敏和 stderr 结构化输出不变。
5. 覆盖已存在大 `walker.log` 时会在写入前轮转。
6. 修改 `src/core/logger.js` 使测试通过。

## 验证命令

```powershell
node --test "test/logger.test.js" "test/log-rotation.test.js"
```
