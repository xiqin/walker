# T2 迁移 daemon 后台运行态路径并补测试

## 目标

把 `walker start/status/logs/stop` 使用的 pid 文件与后台 stdout/stderr 日志迁移到 Walker 数据目录，避免 npm 全局包写入安装目录。

## 涉及文件

- `src/cli/daemon.js`
- `src/index.js`
- `test/daemon.test.js`
- `README.md`

## 实现步骤

1. 在 daemon 中新增或内联数据目录解析逻辑：优先 `WALKER_DATA_DIR`，否则用户主目录下 `.walker`。
2. 支持 `~`、`~/`、`~\` 展开，并与 `src/app/bootstrap.js` 的现有语义保持一致。
3. 将 `PID_FILE` 改为数据目录下 `walker.pid`。
4. 将后台 stdout/stderr 日志目录改为数据目录下 `logs/`。
5. 保持 `start`、`stop`、`status`、`logs` 对外输出和行为语义不变，仅路径位置变化。
6. 更新 CLI help 和 README 中的后台日志路径说明，避免仍指向包安装目录下的 `logs/`。
7. 更新 daemon 测试，覆盖默认数据目录、显式 `WALKER_DATA_DIR`、不使用包安装目录、start 创建新日志目录。

## 验收映射

- REQ-002-B01：未配置 `WALKER_DATA_DIR` 时，pid/log 位于默认 `~/.walker`。
- REQ-002-B02：配置 `WALKER_DATA_DIR` 时，pid/log 位于配置目录。
- REQ-002-B03：路径计算不再以包安装目录作为 pid/log 根目录。
- REQ-002-B04：`start` 写入、`stop/status` 读取同一个数据目录 `walker.pid`，运行状态转换语义不变。
- REQ-002-B05：`start` 先确保数据目录下 `logs/` 存在，再打开 stdout/stderr 日志文件。
- REQ-003-B01：不修改 `src/index.js` 默认前台启动分支。
- REQ-003-B02：daemon 子命令语义保持，现有 daemon 测试继续通过。
