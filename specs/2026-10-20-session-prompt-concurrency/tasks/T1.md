# Task 1：缩短路由锁并验证消息调度

## 描述

将消息的路由锁限制在向会话队列提交提示词的阶段，锁外保留原有异步结果语义，并验证跨会话并发与原有互斥不变量。

## 依赖

- 前置 task：无。
- 外部依赖：无新增依赖。

## 涉及文件

| 操作 | 文件路径 | 说明 |
| ---- | -------- | ---- |
| 修改 | `src/dispatch/message-dispatcher.js` | 仅调整路由锁与提示词 Promise 的等待边界，不修改对外接口与路由规则 |
| 修改 | `test/message-dispatcher.test.js` | 增补同 route 跨会话、同会话、命令互斥、失败与返回语义的行为回归 |

## 复杂度

中等：需要区分锁任务的完成与其返回的提示词 Promise，避免 Promise 同化造成锁仍等待提示词结束。

## 实现步骤

- [ ] 查看 `handleIncomingMessage`、`_enqueueRouteLock`、`_enqueuePrompt` 与命令的锁调用方式，核对既有测试及路由焦点行为。
- [ ] 将 `_enqueuePrompt` 的 Promise 以不被路由锁任务同化的形式提交，待路由锁释放后再等待提示词完成；保留有效路由键、异常及结果返回语义，不引入跨会话全局等待。
- [ ] 重构审查后补充行为验证，确保不改变命令锁的持续范围，不改变 `_promptQueues` 的会话粒度与清理机制。
