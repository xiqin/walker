# Task 3: 引用路由与出站绑定集成

## 描述

在 `MessageDispatcher` 中实现入站引用目标解析、有效 route 投递、可观测字段和飞书发送成功后的统一消息绑定记录。

## 依赖

- 前置 task：T1、T2
- 外部依赖：现有 Feishu API 返回结构、dispatcher route lock 与 session prompt queue

## 涉及文件

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 修改 | `src/dispatch/message-dispatcher.js` | 新增 target resolver、effective event 构造、引用路由日志/admin event 字段、发送成功后记录飞书 messageId 绑定 |
| 修改 | `test/message-dispatcher.test.js` | 覆盖引用路由、降级、thread fallback 优先级、出站记录和记录异常隔离 |

## 复杂度

high，原因：同一文件内涉及入站路由、并发锁、回复上下文、日志和出站 API 成功路径，需要保护现有焦点与 thread fallback 兼容行为。

## 实现步骤

- [ ] 新增 `_resolveIncomingTarget(event, sourceRouteKey)`，按 parentId 映射、route focus、thread root fallback、unbound 的优先级返回 `{ session, routeKey, routedBy }`。
- [ ] 引用命中时构造 effective event：`routeKey` 使用映射或 session route，`sessionId` 使用目标 session，`routedBy` 为 `quoted-message`，并保留 `sourceRouteKey`。
- [ ] 将 `touchRoute`、`_enqueueRouteLock`、`_replyCtx` 和 prompt event 使用 effective route/session，不修改任何 route focus。
- [ ] 在 incoming admin event 或日志中记录 `parentId/sourceRouteKey/effectiveRouteKey/routedBy`。
- [ ] 在 `_callFeishu` 成功返回后调用 `_recordFeishuMessageBindings(methodName, args, result, context)`，只记录能提取新 messageId 且能确定 sessionId 的发送方法。
- [ ] 实现 messageId 提取兼容字符串、数组、`data.message_id`、`data.messageId`、`message_id`、`messageId`。
- [ ] 捕获记录异常并记录 methodName/sessionId/messageId 上下文，确保 `_callFeishu` 返回原发送结果。
- [ ] 增加 dispatcher 测试覆盖引用命中、无效引用降级、thread fallback 优先级、route lock、出站多形态记录和记录失败隔离。
