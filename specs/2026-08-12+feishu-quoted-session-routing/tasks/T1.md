# Task 1: 平台消息索引状态

## 描述

在 `SessionService` 中新增持久平台消息索引，支持飞书 messageId 到 session/route/chat 的记录、解析、剪枝和清理。

## 依赖

- 前置 task：无
- 外部依赖：现有 session state store

## 涉及文件

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 修改 | `src/core/session-service.js` | 初始化 `platformMessages`，新增记录、解析、容量剪枝和删除 session 清理逻辑 |
| 修改 | `test/session-service.test.js` | 增加平台消息映射的状态、边界、恢复和性能路径测试 |

## 复杂度

medium，原因：状态结构变更必须兼容旧 state，并且删除与剪枝路径需要避免误删有效映射。

## 实现步骤

- [ ] 在 state 初始化路径补齐 `platformMessages` 容器和 `feishu` 平台对象。
- [ ] 新增 `recordPlatformMessage(platform, messageId, info)`，写入 `sessionId/routeKey/chatId/kind/createdAt` 并对同 messageId 更新为最新值。
- [ ] 在记录路径实现每平台最多 5000 条的最旧记录剪枝。
- [ ] 新增 `resolveSessionByPlatformMessage(platform, messageId, options)`，校验空 messageId、chatId、session 存在性和 deleted 状态，返回 `{ session, routeKey, mapping }` 或 `null`。
- [ ] 在 `deleteSession(sessionId)` 清理指向该 session 的平台消息映射。
- [ ] 增加单元测试证明旧 state 自动补齐、记录更新、无效映射不投递、容量剪枝和删除清理。
