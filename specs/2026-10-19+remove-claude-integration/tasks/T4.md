# Task 4: 飞书命令和消息失败关闭

## 描述

飞书 `/new claude`、`/attach claude`、自动绑定、卡片动作和旧 Claude 会话消息都在 driver 调用前拒绝，OpenCode attach 保持原路径。

## 依赖

- 前置 task：无
- 外部依赖：无

## 涉及文件

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 修改 | `src/dispatch/message-dispatcher.js` | 删除 Claude attach、自动绑定和 prompt 准备 |
| 修改 | `src/dispatch/question-handler.js` | Claude 提问回复不再写 TUI |
| 修改 | `src/platform/feishu/cards.js` | 卡片不再生成 Claude 命令 |
| 修改 | `src/platform/feishu/commands.js` | attach 帮助只描述 OpenCode |
| 修改 | `test/message-dispatcher.test.js` | 覆盖拒绝、幂等、并发和 OpenCode 回归 |
| 修改 | `test/question-handler.test.js` | 覆盖提问回复拒绝 |
| 修改 | `test/feishu-cards.test.js` | 覆盖卡片不再发出 Claude 命令 |
| 删除 | `test/claude-attach-list.test.js` | 旧 Claude attach 列表测试不再适用 |

## 复杂度

high，原因：dispatcher 同时拥有命令、普通消息、自动绑定和状态展示，漏一条分支就会重新扫描 Claude transcript。

## 实现步骤

- [ ] 在 `_cmdNew` 中，agent 精确为 `claude` 时先返回 `claude_removed` 并发送统一错误卡片，不调用 `registry.get` 或 `createSession`。
- [ ] `_cmdAttach` 看到首参 `claude` 时同样拒绝，不再进入 UUID、分页或搜索逻辑。
- [ ] 删除 `_cmdAttachClaude`、`_attachClaudeSession`、`_prepareClaudeAgentRef`、`_tryAutoBindClaudeRoute`、`_managedClaudeSessionIds` 和 `_findSessionByClaudeId`。
- [ ] 普通消息、cancel 和 watch 在会话 agent 为 `claude` 时拒绝，不调用注入 driver。
- [ ] question handler 对 `request.agent === 'claude'` 在 driver 调用前返回 `claude_removed`。
- [ ] 卡片不再包含 `cmd:/attach claude` 或 `cmd:/new claude`。旧 Claude 会话可显示为不可用，按钮不得触发接入。
- [ ] `COMMANDS.attach.usage` 改为 `/attach [session_id]`，描述不再提及 Claude。
- [ ] `/status` 或等价状态输出对当前 Claude 会话包含统一移除消息，且不改写记录。
- [ ] `/new`、无 agent 的 `/attach` 仍走 OpenCode。`/new Claude` 保持未知 agent 的 driver not found。
- [ ] 拒绝路径不读取 `~/.claude`，日志不含消息正文哨兵。
