# Task 2: 记录回归与真实加载证据

## 描述

运行已修复代码的回归命令和隔离的真实 V2 CLI 加载探针，并把模拟结果、真实加载结果和未验证的飞书往返分开写入报告。

## 依赖

- 前置 task：T1
- 外部依赖：本机 `opencode` 可执行文件。没有该命令或没有安全的飞书认证时，只记录未验证，不伪造成功。

## 涉及文件

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 创建 | `specs/2026-10-19-opencode-v2-cli-plugin-fixes/probe-opencode-v2-cli-load.mjs` | 在临时 `XDG_CONFIG_HOME` 安装并探测真实 CLI 是否加载 V2 入口 |
| 创建 | `specs/2026-10-19-opencode-v2-cli-plugin-fixes/test-report.md` | 命令、退出码、red/green、真实加载和未验证项 |
| 读取 | `specs/2026-10-19-opencode-v2-cli-plugin-fixes/red-evidence.md` | 引用 T1 修复前的失败输出 |

## 复杂度

medium，原因：要区分自动化通过、真实进程证据和外部环境缺失，但不能改产品代码。

## 实现步骤

- [x] 编写探针：创建临时配置根目录并设置 `XDG_CONFIG_HOME`，调用已修复的 `installHookPlugin` 写入 V2 入口；不读取或修改用户主目录配置。
- [x] 探针调用本机 `opencode`，使用不会进入交互飞书会话的加载路径。记录命令、版本、退出码，以及能证明 V2 入口被加载或导入失败的日志。
- [x] 若找不到 `opencode`、命令超时，或输出不能证明入口已执行，探针以非零状态结束，并打印失败阶段。不得输出令牌、密码或消息正文。
- [x] 运行 T1 的相关测试、`npm run lint` 和 `npm run check`。任一命令失败时停止把该项写成通过，先回到 T1 修复。
- [x] 写 `test-report.md`：引用 `red-evidence.md` 的修复前失败，列出每条命令和退出码，单列真实 CLI 探针结果。
- [x] 检查是否存在可安全使用的飞书认证。没有安全往返条件时，报告写明“真实飞书往返未验证”，不得把模拟测试描述成真实往返通过。
