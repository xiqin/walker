# Task 1: 修复插件生成与安装保护

## 描述

让生成的桥接只上报本轮回复、按可见字段回填表单，并让安装器在正确目录原子注册严格的 V2 入口和独立的 V1 入口。

## 依赖

- 前置 task：无
- 外部依赖：本机不需要飞书。V2 入口测试用临时目录模拟 `@opencode/plugin/tui`，不把该包加进项目依赖。

## 复杂度

high，原因：同一生成字符串同时承担回复状态、表单契约和两个入口，安装器还要保护用户配置。

## 固定设计

- `getPluginSource(port, token, heartbeatIntervalMs)` 继续返回共享桥接源码，并导出可直接加载的 `setup`。行为测试加载这份源码，不经过会导入 `@opencode/plugin/tui` 的 V2 入口。
- 新增 `getV2PluginEntrySource()`。它生成的 `walker-tui-plugin.js` 只有顶层 `import { Plugin } from '@opencode/plugin/tui'`、导入同目录桥接，以及 `export default Plugin.define({ id: 'walker-tui-bridge', setup })`。禁止 `try/catch` 后返回 `{ define(plugin) { return plugin; } }`。
- 新增 `getV1PluginEntrySource()`。它生成独立的 `walker-tui-plugin-v1.js`，调用同一 `setup`，不导入 `@opencode/plugin/tui`，也不在 V2 导入失败时被加载。
- 共享桥接写入 `walker-tui-bridge.js`。把源码版本标记从 16 升到 17，使已安装旧文件会被升级。
- 保留 `installHookPlugin` 的现有选项和 `getPluginSource` 导出。`src/cli/init-command.js` 与 `src/app/bootstrap.js` 不改调用方式。
- 配置目录优先级：显式 `opencodeConfigDir`，否则 `XDG_CONFIG_HOME/opencode`，否则 `os.homedir()/.config/opencode`。
- `cli.json.plugins` 已存在且不是数组时返回可诊断错误，不写插件文件，不改 `cli.json` 字节。
- 先把新文件写到同目录临时名，成功后再改名覆盖。改名完成前失败只删除临时文件，原插件、原配置和其他插件保持可用。
- 只有文件内容含 `Walker TUI bridge` 或 `Walker auto-attach hook plugin`，或 URL 与本次安装器写出的 Walker URL 完全相同，才迁移或移除。仅文件名相同不能删除。
- `cli.json.plugins` 只注册 V2 入口。可识别的旧 Walker `tui.json` 注册改为 V1 入口，不把 V1 入口写入 `cli.json`。
- 飞书服务密码不得进入生成源码、配置、返回值或日志。Walker 令牌只保留在桥接鉴权常量，不进入日志和安装结果。

## 实现步骤

- [ ] 先在 `test/opencode-v2-cli-plugin.test.js` 增加失败用例：旧回复已缓存时提前触发完成事件；隐藏字段位于首、中、尾时按序号回填会错位。运行并确认失败，把命令和断言输出写入 `red-evidence.md`。
- [ ] 修改 `finalEvents` 与 `handleSessionIdle`：只采用当前 delivery 开始后新出现、且带完成标记的助手消息。缓存没有该消息时不选上一轮已完成消息，不上报 final。
- [ ] 只有 `report` 成功后才把消息 ID 放入 `sentAssistantIds` 并移除 active delivery。上报失败或缓存同步失败时保留 delivery 和心跳，后续完成事件可再上报一次。成功后的重复事件不再上报。
- [ ] 空消息、没有完成标记、缓存读取抛错时不发送 final，也不把 delivery 标成错误完成。缓存随后出现本轮回复时仍能上报该回复的文本、工具和用量。
- [ ] `questionsFromForm` 继续只发送可见字段。`formAnswerFromWalker` 只按这些可见字段的 `key` 回填；数值和整数在合法时转为数字。缺失、非数字、非整数字段返回可诊断失败，不调用 `form.reply`，并保持该问题可重试。
- [ ] 删除插件日志中的消息正文、完整 delivery 对象、令牌和密码。成功和失败日志保留 delivery ID、类型和失败阶段。
- [ ] 按固定设计拆出桥接、V2 入口和 V1 入口。V1 模拟加载仍执行 register、poll、events、dispose。V2 入口在临时目录缺包或导出没有 `Plugin.define` 时导入失败，且没有轮询；补上有效导出后重新导入只建立一条桥接。
- [ ] 按固定设计修改安装器。默认路径测试必须同时隔离 `HOME` 与 `XDG_CONFIG_HOME`，避免写入用户真实配置。二次安装不重复注册、不改无关字段。
- [ ] 更新三个既有插件测试里对单文件内容、版本 16 和“同名路径一律删除”的断言，使其验证新的三个文件和精确迁移规则。
- [ ] 运行下方测试命令。若 `test/integration-feishu-question.test.js` 因旧错位或正文日志失败，只改对应断言，不改飞书协议。
