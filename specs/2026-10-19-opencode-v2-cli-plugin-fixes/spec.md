# OpenCode 终端桥接插件可靠性修复 — 需求规格

## 1. 概述

**需求来源**：V2 迁移代码审查及用户确认的双入口兼容选择。
**需求类型**：已定位缺陷修复。
**选定方案**：V2 CLI 插件严格导入 `@opencode/plugin/tui`；V1 TUI 插件使用独立入口。复用现有 Walker 桥接协议及主体逻辑，避免维护两套事件处理器。

候选方案及取舍：

1. **双入口（已选）**：V2 加载失败明确暴露，V1 仍可按旧配置加载；需多维护一个入口和安装验证。
2. **仅保留 V2**：实现最小、加载错误清晰；不再支持现有 V1 终端。
3. **单入口静默回退**：对旧测试最省事；会掩盖 V2 导入错误，因此不采用。

## 2. 功能清单

| Requirement ID | 功能点 | 优先级 | 可验证验收标准 |
| --- | --- | --- | --- |
| REQ-001 | 完成事件只上报本轮已完成的助手回复 | P0 | 消息缓存延迟、空消息及旧回复存在时，不提前终结或错发旧回复；成功时恰好终结当前 delivery 一次。 |
| REQ-002 | V1/V2 独立入口与加载失败可诊断 | P0 | V2 入口由真实 `Plugin.define` 定义且导入失败不静默降级；V1 入口仍执行现有 register/poll/events/dispose 协议。 |
| REQ-003 | V2 表单答案按可见字段键回填且保持类型 | P0 | 隐藏字段穿插、数值、布尔、多选及选项标签映射时，提交的 `Form.Answer` 符合 V2 契约。 |
| REQ-004 | 安装器遵循终端配置位置并保护现有设置 | P0 | 默认遵循 `XDG_CONFIG_HOME`，显式目录优先；非法 `cli.json.plugins` 不覆盖；V1/V2 入口按对应配置注册、去重且保留其他设置。 |
| REQ-005 | 桥接日志不暴露消息正文或凭据 | P0 | 日志仅包含必要的 delivery 元数据；飞书消息、服务密码及 Walker 令牌不进入安装日志和插件运行日志。 |
| REQ-006 | 回归验证覆盖模拟与真实加载 | P1 | 先有可重复失败用例，再通过相关测试、全量 lint/检查，并在可用环境验证 V2 CLI 实际加载；真实飞书往返若环境不足则明确标记未验证。 |

`requirements.json` 包含上述所有 REQ 和逐行为验收条款。首次复现命令已证明非法 `cli.json.plugins` 会被覆盖；修复前必须对缓存竞态、表单错位建立等价的失败信号。

## 3. 接口和数据边界

- 不改变 Walker 的 register/poll/events/dispose HTTP 路径、鉴权方式和 delivery 状态协议。
- 保持现有显式 `OPENCODE_SERVER_URL` 优先级及 HTTP/SSE 迁移行为。
- V2 CLI 插件注册于全局 `cli.json.plugins`；V1 入口独立于 V2 文件和配置，不以 V1 入口充当 V2 导入失败回退。
- 默认配置根目录是 `$XDG_CONFIG_HOME/opencode`（设置时）或 `~/.config/opencode`；调用方显式给出 `opencodeConfigDir` 时优先使用。
- 对已有 V1 注册仅在能够确定属于 Walker 时迁移；不得误删同名的其他插件、覆盖未识别的用户配置或把服务端旧 hook 当作 V2 插件加载。
- V2 表单回复对象以字段 `key` 为键；只有可见字段与 Walker 发出的可答题顺序对应。缺失、不可转换、隐藏字段的处理必须在失败用例中定义并验证，不能生成错位答案。

## 4. 异常与边界

| 场景 | 预期行为 |
| --- | --- |
| 完成事件早于缓存同步 | 同步后定位当前轮次；失败时不把上一轮助手消息作为当前轮完成。 |
| 终结上报失败 | 不永久标记为已发送；后续事件或可控重试仍有恢复机会。 |
| V2 插件包无法导入 | 明确失败，可通过终端加载错误诊断；绝不静默使用伪 `Plugin.define`。 |
| `plugins` 配置不为数组 | 不写插件或 `cli.json`；返回可诊断错误。 |
| 隐藏、条件字段、数值输入 | 不错位、不把数值作为字符串提交；非法值不能假装成功。 |
| 已有其他插件配置 | 原顺序、其他字段与其他插件保持不变。 |

## 5. 验证和非目标

- 在隔离配置下验证真实 OpenCode V2 终端加载，不覆盖用户主配置；测试 V1 入口的旧通信回归。
- 若没有飞书认证或无法安全发起真实消息，只报告模拟往返已通过，真实飞书往返待验证。
- 不改动 HTTP/SSE 驱动、其他聊天渠道、用户密码配置、服务发现优先级；不提交 Git。
- 当前工作树已有用户未提交改动。隔离工作树不能丢失这些改动；若现有流水线的隔离步骤无法安全承接，必须先停下说明并请求选择。
