# Task 3: 输入仲裁与 ClaudeDriver PTY prompt 改造

## 描述

将 `ClaudeDriver` 从每轮 `kscc --print` 改为使用 broker 托管的长期 PTY，并实现飞书 prompt 与本地键盘输入的不可交错仲裁。

## 依赖

- 前置 task：T1、T2
- 外部依赖：无新增

## 涉及文件

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 修改 | `src/drivers/claude-driver.js` | create/resume/prompt/stop/delete 改接 PTY broker，移除飞书 prompt 的 `--print` spawn 路径 |
| 修改 | `test/claude-driver.test.js` | 覆盖长期PTY、输入事务、队列上限、无效prompt和禁止第二进程 |

## 复杂度

high，原因：这是用户可见行为的核心切换，必须同时保护首次创建、连续prompt、本地lease和危险状态。

## 实现步骤

- [ ] 步骤 1：`createSession()` 立即创建 broker runtime，agentRef 使用 `transport: pty-attach`、`runtimeId`、`claudeSessionId`、`processGeneration` 和 terminal 状态。
- [ ] 步骤 2：`prompt()` 调用 broker 的 `submitPrompt`，不再调用 `_buildPromptArgs()` 或 spawn `kscc --print`。
- [ ] 步骤 3：实现飞书 prompt 校验：空白、超长和非字符串 payload 返回稳定错误，不进入队列或PTY。
- [ ] 步骤 4：实现 writer lease：本地编辑未提交时飞书prompt排队，Enter、Ctrl+C、detach或超时释放 lease 后继续消费队列。
- [ ] 步骤 5：实现默认5条有界FIFO，满队列明确拒绝；busy或permission状态下普通飞书文本不直接写入PTY。
