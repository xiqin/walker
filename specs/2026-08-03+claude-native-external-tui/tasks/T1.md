# Task 1: Claude PTY broker 与 runtime 生命周期

## 描述

建立 Claude 专用 PTY runtime 和 broker，为每个 Claude 会话托管唯一长期 `kscc` TUI 进程、输出缓冲、状态转换和恢复启动参数。

## 依赖

- 前置 task：无
- 外部依赖：`node-pty`

## 涉及文件

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 创建 | `src/drivers/claude-pty-runtime.js` | 封装 PTY spawn、resize、write、kill tree 和 ConPTY 不可用诊断 |
| 创建 | `src/drivers/claude-pty-broker.js` | 管理 runtimeId、claudeSessionId、processGeneration、输出回放、状态转换和等待者失败 |
| 创建 | `test/claude-pty-broker.test.js` | fake PTY 覆盖启动、恢复、失败、退出、缓冲上限和日志字段 |
| 修改 | `package.json` | 增加 PTY 运行依赖 |
| 修改 | `package-lock.json` | 锁定新增依赖 |

## 复杂度

high，原因：这是后续 attach、prompt、恢复和停止的共享状态基础，必须一次定义稳定接口。

## 实现步骤

- [ ] 步骤 1：新增 PTY runtime 工厂，支持注入 fake pty 以便单元测试，真实实现加载 `node-pty` 并在不可用时返回稳定错误。
- [ ] 步骤 2：新增 broker，提供 `createRuntime`、`resumeRuntime`、`getRuntime`、`stopRuntime`、`deleteRuntime`、`writeInput`、`resize`、`subscribeOutput` 接口。
- [ ] 步骤 3：新建会话参数使用 `kscc --session-id <uuid>`，恢复参数使用 `kscc --resume <uuid>`，禁止使用 `--continue`。
- [ ] 步骤 4：实现 runtime 状态 `starting`、`active`、`stopped`、`error`，并在 exit/error 时失败所有 pending waiter 和队列项。
- [ ] 步骤 5：实现 1 MiB 默认输出回放缓冲和结构化生命周期日志，不记录完整 prompt、token 或敏感 env。
