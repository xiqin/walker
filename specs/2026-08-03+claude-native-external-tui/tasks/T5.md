# Task 5: Dispatcher 持久化、停止删除与旧引用迁移

## 描述

把新的 Claude `agentRef` 形态接入现有 session 持久化、watch、stop/delete 和旧引用恢复路径，确保有效UUID可迁移、无效引用fail closed。

## 依赖

- 前置 task：T3、T4
- 外部依赖：无

| 操作 | 文件路径 | 说明 |
|------|----------|------|

| 修改 | `test/message-dispatcher.test.js` | 覆盖旧引用迁移、缺UUID fail closed、agentRef更新和watch分发 |

## 复杂度

medium，原因：主要是现有 dispatcher 对新 agentRef 的兼容和持久化，不新增底层协议。

## 实现步骤

- [ ] 步骤 1：确认 `getAgentRefId()` 和 `hasAgentSessionRef()` 支持 `claudeSessionId` 与 `runtimeId`，不影响 OpenCode ref。
- [ ] 步骤 2：在创建、prompt后状态更新、resumeSession、stop/delete路径中持久化完整 Claude PTY agentRef。
- [ ] 步骤 3：旧 Claude ref 有合法 `claudeSessionId` 时迁移为 `transport: pty-attach` 并走 driver resume；缺失或非法UUID时明确失败。
- [ ] 步骤 4：`watchSession` 继续接入既有分发链路，本地TUI JSONL事件可发送到对应飞书会话。
- [ ] 步骤 5：增加测试确保不使用 `--continue` 或最近会话猜测恢复。
