# Task 2: Dispatcher 与进度卡片运行信息透传

## 描述

在 `MessageDispatcher` 调用飞书 API 前整理当前会话模型与上下文元数据，并以可选参数传入 T1 的页脚注入逻辑。进度卡片创建与更新链路也必须携带同一 runtime metadata，确保 `bootstrap` wrapper 最终透传给 `replyCard`/`patchCard`。

## 依赖

- 前置 task：T1
- 外部依赖：无

## 涉及文件

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 修改 | `src/dispatch/message-dispatcher.js` | 在 `_callFeishu` 或相邻私有辅助方法中生成 runtime footer metadata，并保持重试逻辑不变。 |
| 修改 | `src/dispatch/progress-renderer.js` | 完整回复、legacy 回复和进度卡片创建/更新调用传递 `sessionId` context，并移除旧模型-only footer 拼接路径。 |
| 修改 | `src/app/bootstrap.js` | 让进度卡片 wrapper 接收 runtime 参数，并透传给底层 `replyCard`/`patchCard`。 |

## 复杂度

medium，原因：需要在不改变现有命令调用签名语义、进度卡片 wrapper 兼容性和重试行为的前提下，把可选运行信息传入不同飞书 API 方法。

## 实现步骤

- [ ] 增加私有方法，根据 `_callFeishu` 的 `context`、routeKey 和 sessionService 读取当前 session。
- [ ] 复用已有模型解析约定，优先传递 `session.model`，其次传递配置默认模型，缺失时允许 T1 回退 `unknown`。
- [ ] 从 `context`、turn state 或当前 session 中收集可取得的上下文大小字段，不存在时不构造假值。
- [ ] 对支持页脚的方法追加最后一个可选 runtime 参数；不支持页脚的方法保持原 args。
- [ ] 为完整回复、legacy 回复、watch progress 和 progress card 更新调用补齐 `sessionId` context。
- [ ] 让 `sendProgressCard` 与 `updateProgressCard` wrapper 接收 runtime 参数，并透传给 `replyCard`/`patchCard`。
- [ ] 保持 retryable 正则、`maxAttempts`、fallback 返回值和日志上下文字段不变。
- [ ] 确保页脚 metadata 构建不调用 driver 的 `listModels`、消息读取或任何外部 API。
