# Task 2: Claude driver 问题答案写入与输入仲裁

## 描述

在 Claude driver 层实现只写原托管 runtime 的问题答案输入、键序列生成、不可写失败分类和短租约仲裁，不再通过 resume 新进程伪装成功。

## 依赖

- 前置 task：T1
- 外部依赖：Claude TUI 当前问题界面键盘行为

## 涉及文件

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 修改 | `src/drivers/claude-driver.js` | replyQuestion、键序列生成、runtime 可写判断、输入租约 |
| 修改 | `src/providers/provider-catalog.js` | Claude questionReply 能力标记为 degraded |
| 修改 | `test/claude-driver.test.js` | 单选、多选、不可写、租约和 fallback 测试 |
| 修改 | `test/claude-tool-parity.integration.test.js` | Claude/OpenCode 能力契约回归 |
| 修改 | `test/provider-catalog.test.js` | provider catalog 能力状态回归 |

## 复杂度

high，原因：飞书答案要转为 TUI 可消费输入，并且必须避免与本地输入交错或写入错误进程。

## 实现步骤

- [ ] 为 `replyQuestion` 增加 managed runtime 可写检查，非原 runtime 可写时抛明确错误。
- [ ] 根据原始 questions/options 生成单选和多选键盘序列，无法匹配时进入安全降级。
- [ ] 引入短租约或原子写入保护，保证问题键序列不被本地输入插入。
- [ ] 将 PTY 写入失败、runtime stopped、lease expired 分类为用户可理解状态。
- [ ] 更新 Claude provider capability 为 degraded，并保持 permission reply 仍按 unsupported/degraded 表达。
