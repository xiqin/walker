# Task 4: 飞书 route 绑定、问题状态机与只读降级

## 描述

在 MessageDispatcher 和 QuestionHandler 层实现托管 Claude route 绑定、外部只读降级、飞书答案 awaiting 状态、真实 tool_result ACK、本地先答处理和结构化日志。

## 依赖

- 前置 task：T1、T2、T3
- 外部依赖：飞书卡片 API、SessionService route/focus

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 修改 | `src/dispatch/message-dispatcher.js` | Claude route 绑定、managed/external-readonly 分流、watch 事件分发 |
| 修改 | `src/dispatch/question-handler.js` | question 状态机、answer submit、awaiting ACK、readonly/timeout/card patch |
| 修改 | `test/question-handler.test.js` | 状态机、无效答案、ACK、只读、日志测试 |
| 修改 | `test/integration-feishu-tui-sync.test.js` | 飞书 route、Claude question、answer-to-ACK 集成测试 |

## 复杂度

high，原因：该任务连接飞书、session route、Claude event 与卡片状态，竞态和终态处理必须严格。

## 实现步骤

- [ ] 让 `/new claude` 或 cwd route 优先绑定 walker-managed Claude runtime；外部 transcript 发现标记 external-readonly。
- [ ] 问题卡片创建时保存 runtimeId、toolUseId、requestID、questions、owner、inputWritable。
- [ ] 飞书答案提交后，Claude managed 会话进入 `awaiting_tool_result`；无效答案、只读会话和过期请求不写 PTY。
- [ ] 监听 matching `tool_result`，将 awaiting 请求转为 `answered`；本地先回答时转为 `answered_elsewhere`。
- [ ] 为 runtime、question、answer、ACK、降级和异常添加结构化日志与脱敏。
