# Task 3: Admin Config 与 Session Agent 泛化

## 目标

把 Claude 配置纳入现有配置摘要、编辑 allowlist 与 admin 可见性，并将底层 agent session 创建逻辑从 `opencode` 硬编码泛化为按 `session.agent` 获取 driver。

## 依赖

依赖 T1 的 `ClaudeDriver` 与 T2 的 provider/config key 接入。

## Affected Files

- `src/admin/config.js`
- `src/admin/config-editor.js`
- `src/admin/session-admin.js`
- `src/config/env.js`
- `test/admin-observability-config.test.js`
- `test/admin-config-event.test.js`
- `test/admin-core-api.test.js`
- `test/admin-ui-dashboard-connections.test.js`
- `test/config-env.test.js`
- `test/session-service.test.js`

## 实现步骤

## Checklist

- [ ] 在 `src/admin/config.js` 新增 `claude` 配置组或合理复用现有分组，并加入 `CLAUDE_CMD`、`CLAUDE_MODEL`、`CLAUDE_FALLBACK_MODEL`、`CLAUDE_AGENT`、`CLAUDE_PERMISSION_MODE`、`CLAUDE_ALLOWED_TOOLS`、`CLAUDE_DISALLOWED_TOOLS`、`CLAUDE_CONFIG_DIR`、`CLAUDE_PROMPT_TIMEOUT_MS`。
- [ ] 为 `CLAUDE_PROMPT_TIMEOUT_MS` 使用正整数校验；permission mode 使用可验证枚举或普通字符串校验时必须保持错误可诊断。
- [ ] 确认 `src/admin/config-editor.js` 的 allowlist 与 validation 可覆盖新增字段，`.env` 更新仍保持原子写入和未知键保留。
- [ ] 修改 `src/admin/session-admin.js:createSession`，当 `createAgentSession` 为 true 时按 `session.agent` 获取 driver 并调用 `driver.createSession()`；不存在 driver 时记录清晰错误。
- [ ] 保持默认 `WALKER_DEFAULT_AGENT` 为 `opencode`，只在显式设置 `claude` 时使用 Claude driver。

## Acceptance Mapping

覆盖 `REQ-001`、`REQ-007`、`REQ-008` 中与 Claude 配置可见性、配置编辑校验、通用 session 创建和默认 OpenCode 兼容相关的 behavior。

## 测试步骤

1. 更新 admin/config 测试，断言 `buildConfigSummary()` 返回 Claude 字段、非敏感、可编辑、provider catalog configKeys 可追踪。
2. 更新 config editor 测试，断言合法 Claude 字段可写，非法 timeout 返回 validation error，非法请求不产生不可追踪状态。
3. 更新 session/admin/core API 测试，断言 `agent=claude` 且 `createAgentSession=true` 时调用 Claude driver，默认未配置时仍使用 opencode。

## 完成标准

Admin 层能显示和保存 Claude 非敏感配置，session 创建不再只支持 OpenCode 底层 agent session，OpenCode 默认路径保持不变。
