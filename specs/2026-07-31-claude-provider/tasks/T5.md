# Task 5: Claude/kscc TUI 会话等价链路

## 目标

让 `claude` provider 在 Walker 层提供与 OpenCode 等价的会话体验：飞书 `/new claude <title>` 创建 session 后拉起可见 Claude/kscc 交互式终端窗口，普通飞书消息继续进入同一 Claude/kscc 会话，上下文、停止、删除、恢复、watch/refresh 和状态展示可诊断，同时不伪造或污染 OpenCode 专属 `opencodeSessionId`、TUI bridge watcher 或 sqlite 语义。

## 依赖

依赖 T1 的 `ClaudeDriver` 基础接口、T2 的 provider catalog/bootstrap 注册、T3 的 admin/session agent 泛化。

## Affected Files

- `src/drivers/claude-driver.js`
- `src/dispatch/message-dispatcher.js`

- `src/admin/session-admin.js`

## Checklist

- [ ] 为 `ClaudeDriver` 增加可注入 terminal launcher/window registry 能力，`createSession()` 能在配置可用时启动 Claude/kscc 交互式终端窗口，并在 `agentRef` 记录 `claudeSessionId`、窗口/进程标识、cwd、title、模型和状态。
- [ ] `prompt()` 对同一 Walker session 复用同一 `claudeSessionId` 或可验证 resume 标识，不因飞书消息创建无关后台会话；后台 `--print` fallback 必须在状态中可见。
- [ ] 为窗口启动失败、CLI 缺失、cwd 无效、终端能力不可用、进程提前退出和 stderr 错误提供脱敏且可操作诊断，不把窗口失败回复为完全成功。
- [ ] `ensureWatch`/`refreshWatch` 或等价分支对 Claude session 幂等：活动窗口复用状态，缺失窗口按恢复策略重建或明确返回 unavailable，不重复拉起多个窗口。
- [ ] `provider-catalog`、provider doctor、`/current`、`/list` 和 admin session 状态能展示 Claude 的真实 TUI/window/watch 状态，并区分 active/stopped/failed/unavailable。
- [ ] 保持 OpenCode 默认窗口、watch、TUI bridge 和 sqlite 语义不回归；Claude agentRef 不伪造 `opencodeSessionId`。
- [ ] 所有终端启动和 prompt 路由使用 argv/受控环境，不通过 shell 拼接用户 title、cwd 或 prompt；日志和错误脱敏 `ANTHROPIC_API_KEY` 等敏感值。
- [ ] 列表、doctor、refresh 类命令不得触发真实长 prompt 或无限等待窗口进程，必须受 timeout/状态缓存控制。

## Acceptance Mapping

覆盖 `REQ-010` 的 11 个 behavior：`REQ-010-B01` 到 `REQ-010-B11`。

## 测试步骤

1. 用 fake terminal launcher 覆盖 `/new claude kscc-test` 创建 session 后 launcher 被调用一次、参数含 cwd/title、`agentRef` 含窗口 metadata、catalog `capabilities.tui=true`。
2. 用 fake spawn/launcher 覆盖同一 Claude session 连续 prompt，断言两次 prompt 使用相同 resume/session 标识且没有第二个无关 terminal session。
3. 覆盖 cwd 不存在、`CLAUDE_CMD` 不存在、terminal launcher 抛错、进程 exit code 1/stderr 的错误路径，断言错误可读且脱敏，session/window 状态不残留 running。
4. 覆盖连续 ensureWatch/refresh 三次，断言 launcher 调用次数受控且 window registry 无重复记录。
5. 覆盖 `/current`、`/list`、provider doctor、admin sessions 输出 active/stopped/failed Claude session 状态，且不出现伪造的 `opencodeSessionId`。
6. 运行 OpenCode driver/message-dispatcher/admin 回归测试，确认现有窗口/watch/TUI bridge 行为不回归。

## 完成标准

`REQ-010` 所有 behavior 在 `traceability.json` 中具备真实 tests/evidence；相关定向测试和 `npm test` 通过；飞书手测路径可按 `.env` 中 `CLAUDE_CMD` 指向 kscc.exe 后执行 `/new claude kscc-test` 并看到可见终端窗口。
