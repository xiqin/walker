# Task 2: 单 runtime 生命周期与安全输入事务

## 描述

在 `ClaudeDriver` 内解耦 runtime 可写性与窗口在线状态，保证恢复不弹窗、并发恢复不重复 spawn，并用现有有界仲裁队列把飞书 prompt 安全写入唯一 PTY 后从精确 transcript 收集回复。

## 依赖

- 前置 task：T1
- 外部依赖：现有 PTY broker、bridge sidecar、Claude JSONL transcript

## 涉及文件

| 操作 | 文件路径 | 说明 |
|------|----------|------|
| 修改 | `src/drivers/claude-driver.js` | 调整 create/resume/active/window 语义，收紧恢复互斥、输入事务、队列、生命周期和诊断 |
| 条件修改 | `src/drivers/claude-transcript.js` | 仅在精确路径、cursor 或失败完成测试暴露缺口时最小修复 |
| 修改 | `test/claude-driver.test.js` | 覆盖单 runtime、窗口解耦、仲裁、队列、退出和脱敏 |
| 修改 | `test/claude-transcript.test.js` | 覆盖精确 UUID、cursor、隔离、超时和路径安全 |

## 复杂度

high，原因：同一 driver 中存在 runtime、窗口、输入 lease、权限状态、队列和 transcript 多个相互关联的状态机，需保持原生 TUI 行为不变。

## 实现步骤

- [ ] 先增加失败测试，证明 active runtime 在 detached terminal 下仍 active，且 `resumeSession()` 不调用窗口启动器。
- [ ] 为同一 Claude UUID/runtime 的恢复增加 promise 级互斥或复用，确保并发调用只执行一次 `resumeRuntime`。
- [ ] 保留 `createSession()` 最多一次初始 `_ensureTerminal()`，移除恢复路径的隐式开窗，并让窗口失败不停止 runtime。
- [ ] 让 `isSessionRefActive()` 仅依据可重连 bridge 或 active PTY runtime；terminal 状态只用于展示与显式 attach。
- [ ] 验证 prompt 校验、writer lease、busy/permission 门禁、FIFO 队列、容量上限和各释放路径，缺口只在现有状态机中最小修复。
- [ ] 保证完整 `text + CR` 作为一次 broker 写入，日志只记录来源、长度、队列深度和脱敏标识。
- [ ] 在写入前创建精确 transcript cursor，只读取绑定 UUID 的 cursor 后 assistant 事件；缺失、部分行和超时均失败完成。
- [ ] 验证 PTY 退出会使 runtime 非 active，并让 pending prompt 全部完成为失败。
- [ ] 验证恢复成功后才返回新 runtimeId，失败时不产生指向不存在 runtime 的成功引用。
